# V15 — Tableauの表レイアウト計算（33秒）を切り分ける独立検証版

> **このV15はData Viewerの代替品ではありません。** 既存機能、フィルター動作、列表示、CSVを置き換えません。本番／V10〜V14のファイルは一切変更しません。

## 目的

Tableau Public Desktopの「Computing layouts / 表レイアウト計算」に33秒以上かかる現象について、**表示するマーク数を大幅に減らすと待機時間が短くなるか**を検証する。早くなるかは未確認。Readerページサイズの調整を繰り返す検証ではない。

## 変更点・ユーザー影響

- **従来版:** `表示列` に15列をドラッグしてSummary Data Readerで描画する。
- **この検証版のみ:** 新しい独立Viz Extensionとして、`検証用メジャー（1個）` に連続数値メジャー1個のみを割り当てる。明細15列をTableauのエンコーディングへ入れない。
- **測定:** 「フィールド操作前に時刻記録」→1メジャーを割り当てる→イベントを待つ→待機時間を見る。ログの時間にはドラッグ操作時間も含まれる。Tableau性能記録の`Computing layouts`を併せて確認する。
- **オプションのUnderlying検証:** 別ボタンを押したときに限り`getUnderlyingTablesAsync`→`getUnderlyingTableDataReaderAsync(tableId,1000)`→`getPageAsync(0)`を実行し、時間・総行数・ページ数・列数を表示する。セル値は表示・ログ出力しない。
- **フルデータ権限:** `<permissions><permission>full data</permission></permissions>`を要求。読み込む際、Tableauに権限の許可が表示される場合がある。**許可したくない場合は実行しない**。既存V14には権限を追加していない。
- Tableauがデータを更新・フィルター変更してもUnderlyingは自動取得しない。
- Logical Tableが2個以上なら自動で先頭を選ばず検証を中止する（誤ったテーブルを計測しないため）。
- UnderlyingはSummaryと異なる意味のデータ。**一致しない限り既存Data Viewerへ適用しない。**

## 実機手順（Tableau Public Desktop）

1. **既存ワークブックを複製し、別の新しいワークシート**を作る。既存V14のシートはそのまま保存する。
2. 新シートに `preview/layout-probe-v15.trex` をViz Extensionとして配置する。Full Data権限の確認が出たら、内容を確認して許可するか判断する。
3. Tableauの「ヘルプ → 設定とパフォーマンス → パフォーマンスの記録を開始」で記録を開始する（メニュー名は環境差あり）。
4. V15の「フィールド操作前に時刻記録」をクリックする。
5. 元の50万行データと同じ論理テーブルから **集計された数値メジャー1個のみ**（例: テーブルの行数をCOUNTするメジャー）を「検証用メジャー（1個）」に割り当てる。Detail・Tooltip・他のシェルフにディメンションを入れない。
6. Tableauの「表レイアウト計算」が終わったら、V15の「操作前記録からイベントまで」の秒数と、Tableauの性能記録の`Computing layouts`の値を見る。
7. V15の「Underlying取得を検証」をクリックし、Readerが準備できるか、総行数・列数・API所要時間を確認する。エラーが出たらエラー文も送る。
8. 「計測ログをTSVコピー」からログを取得する。
9. **フィルター試験（任意、別途仕様検証）:** 現行版の業務フィルターと同じ条件にし、Underlying Readerの総行数が期待どおりかを比較する。ソート順・計算フィールド・集計・リレーションシップ・CSV出力の一致は、この版だけでは判定できない。

## 合否

- **第一関門:** 50万行のまま、Tableau性能記録上の`Computing layouts`が33秒より明確に短くなるか（同じ環境で繰り返し測定）。
- **第二関門:** Underlying Readerの準備＋最初の1,000行取得が十分速いか。50万行を取得可能か（`totalRowCount`と`pageCount`）。
- **第三関門:** 現行Summary Dataの列、値、フィルター、行順、計算フィールド、集計結果に必要な意味論が維持できるか。ここを通過するまでは製品実装へ進めない。

**注意:** JavaScriptのイベント時刻はTableau内部のレイアウト計算開始時刻ではない。表レイアウトの33秒を厳密に比較する指標はTableau側のPerformance Recordingを使うこと。

# V13: 初回200行表示の方式比較（Tableau Public Desktop / Excel）

この検証版は既存V11を複製した独立コードです。V10/V11/V12・本番ルートは変更しません。50万行×14列のExcelで、Reader初期化より先に200行を表示できるかを調べます。

## 使用するTREX（両方を同じExcel・同じ表示列で比較）

1. `../firstpaint-v13-reader.trex` — **A: Readerのみ（基準）**
   - `getSummaryDataReaderAsync(200)` → `getPageAsync(0)` → 200行描画
2. `../firstpaint-v13-limited.trex` — **B: 200行先行表示（実験）**
   - `getSummaryDataAsync({maxRows:200,...})` → 200行描画 → Readerを生成 → Reader先頭ページ取得 → 内容比較 → Readerを正式表示
   - 限定取得が失敗・未対応・列不足の場合はReader方式にフォールバック。

両方、Tableauの表示列の割り当てとセルの外観設定・ページ切替・CSV分割出力等を維持。最初のReader生成まではページ切替とCSV出力を不可にします。

## 手順

1. 同じExcel接続、同じ表示列数・順序、同じフィルター条件で2つのTREXを順番に開いて比較する。
2. Tableauで表示列を設定する（初期値が空の場合、最初のV13初期化は計測されてもデータ表示しません）。
3. 必要なら表示列のセットを終えてから、一度「再読み込み」を押し、対象を同じ条件に揃える。
4. 計測パネルで以下を確認し、TSVコピーして比較する。各方式で最低3回、できれば5回以上計測し、実行順を入れ替える。
5. Tableauのフィールド割当を変えた際に「summary-data-changed」が発生した場合は、その自動更新の計測も比較する。イベント発生前のTableau処理は計測対象外。

## 指標

- `API: getSummaryDataAsync(maxRows:200)`: 限定取得APIの応答時間（Bのみ）。
- `API: getSummaryDataReaderAsync(200)`: Readerの生成時間（A/B）。
- `API: getPageAsync(0)`: Reader最初の200行の取得時間（A/B）。
- `初回200行をDOM追加するまで`: V13の`refreshData`開始からHTMLに200行を追加した時点まで。**画面描画完了を意味しません**。
- `Readerでページ移動が可能になるまで`: 同じ基点からReader先頭ページの表示・ページ切替有効化まで。
- `判定: 全セル一致` or `判定: 差異あり`: 先行取得の値とReader先頭ページの表示値を、元のフィールド名による列対応後に1行ずつ比較。行が異なる場合も検出。値の比較はビューアに表示される文字列であり、型・内部値の完全一致の証明ではありません。
- `先行取得失敗: ...`: 非推奨APIの失敗時に原因メッセージを記録します。

## 採用判断

- Bの「初回200行をDOM追加するまで」がAより明確に短く、表示値の比較が連続で「全セル一致」であり、エラー／異常終了が見られないこと。
- Readerの後段の準備完了時間がAより極端に悪化していないこと。
- 先行表示に伴う画面の二重描画・一時的なレイアウト変化が許容範囲であること。
- Bが失敗するか先行取得がReader並みに遅い場合は、**Bを採用せずReader方式を維持する**。

## 制約

- `getSummaryDataAsync`はTableau公式の非推奨APIで、大きなワークシートでは失敗する可能性があります。`maxRows=200`は返却行数の指定であり、Tableau内部の前処理量やSQL実行量を200行へ限定する保証ではありません。
- Bの二段階取得ではReaderの生成は消えません。先行表示が速ければ*見かけの初回表示*が早まるだけです。
- Bで差異が生じた場合はReaderの結果を最終表示に採用します。先行表示した行はその直前にユーザーへ一時表示されるため、本番導入には厳格な判定が必要です。
- Reader処理と非推奨APIを逐次呼びます。Tableau側の処理が増える可能性があります。
- APIの初期化・Tableau内部のフィールド変更イベント前にかかる時間や、HTML要素が実際に画面へペイントされた時刻は計測できません。
- 限定取得に長時間応答がない場合、Promiseが解決するまでフォールバックできません。実運用版にはタイムアウト・破棄方針等の別設計が必要です。
- **最新性**: データが変わるとイベント経由で再取得します。データ変更イベントが届かない更新まで保証するものではありません。

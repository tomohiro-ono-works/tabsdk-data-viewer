# 1,000行一括取得・200行×5ページ表示 — V14

V11を複製した独立検証版です。V10/V11/V12/V13、本番ルートは変更しません。

## 実装

- Reader生成は `worksheet.getSummaryDataReaderAsync(1000, {ignoreSelection:true, applyWorksheetFormatting:true})`。
- UIページサイズは従来通り200行。Tableau Readerの各1,000行ページをJavaScript内で200行ずつ5つに分割して表示します。
- 同じ1,000行の範囲ではAPIへの `getPageAsync` を再実行せず、Readerの取得済み1,000行を1ページ分だけキャッシュします。6ページ目に進むとReaderページ1を取得し、キャッシュを入れ替えます。
- 50万行の場合: Reader 500ページ、画面2,500ページ。0行・1000行未満・端数も対応。
- Tableauのフィルター変更／Summary Data変更イベントを検知したらキャッシュを即時破棄し、従来通りReaderを解放して再生成します。進行中の旧ページ取得がイベント後に完了しても旧内容を表示しないようガードします。
- CSV出力はこれまで通り専用Reader（CSV_PAGE_SIZE=5000）を使用。変更していません。
- 列幅・列固定・ヘッダー設定・セル選択・コンテキストメニューコピー・CSV分割など、既存V11の表示機能を継承します。

## Tableau Public Desktopでの検証

1. `../batch-v14.trex` を登録し、V11と同じExcelデータ・同じ列数に設定。
2. 表が出たら「計測結果」を開き、初回読込で `getSummaryDataReaderAsync(1000)` と `getPageAsync(0) [1,000行]` の時間を確認。
3. 画面を1→2→3→4→5ページと移動。2〜5ページ目は **Readerキャッシュ HIT** で `getPageAsync` が記録されないことを確認。
4. 5→6ページへ進む。 **Readerキャッシュ MISS** と `getPageAsync(1) [1,000行]` が記録されることを確認。
5. 6→7ページ目は再び **HIT**。5ページ目へ戻ると、前のキャッシュを再取得する **MISS**（キャッシュは最新1チャンクのみ）。
6. フィルターを変更した後に表示ページが1に戻ること、Readerが再生成されることを確認。
7. 「全結果をTSVコピー」でV11とV14を比較。TSVには「Readerページ数」「表示ページ数」「Reader取得行数」「Readerキャッシュ」が含まれます。
8. 任意の条件でCSVの分割出力・コピー・列幅なども回帰確認。

## 評価項目

- 最初のReader生成時間: 200行 Readerと1,000行 Readerで差が出るか。*データ条件を揃える*。
- 200行のページ切替: 既存V11はReaderページごとに `getPageAsync` していたが、V14は同一1,000行範囲内の4回分をキャッシュで省略できる。
- 1,000行を取得するAPIの所要時間: 初回ページは以前より遅くなる可能性あり。
- 画面描画時間: 200行のままなので、DOMセル生成数は変更しない。
- **Tableau内部の表レイアウト計算（以前約42秒）**: 取得単位の変更だけでは短縮を保証しない。表レイアウト計算にかかる時間は、このJavaScript計測では確認できない。

## ロジック検証

- JavaScript構文・TREX/HTML参照・ID整合性
- Reader 1000行 / UI 200行のページ換算
- 0, 1, 999, 1000, 1205, 500000行の境界と末尾端数
- 5ページ間のキャッシュHIT、6ページ目のMISS、逆方向への再取得
- Reader解放/再生成時のキャッシュ破棄とReader同時有効数1
- 非同期Reader取得中のデータ変更イベントで旧結果の表示が破棄されること
- TSV書き出しの列数統一とCSV処理の既存コード維持

実際のTableau Public Desktop上での性能・イベント挙動は、まだ実測していません。

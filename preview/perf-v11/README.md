# 性能計測 V11（Tableau Public Desktop + Excel）

このフォルダはV10の機能を保持した性能診断専用の隔離版です。元の `preview/index.html`、`preview/app.js`、`preview/app.css` や本番ルートは変更していません。

## 使用方法
1. 検証用マニフェスト `../perf-v11.trex` をTableau Public DesktopのViz Extensionとして配置します。
2. Excelデータソースのフィールドを「表示列」に登録します。
3. 初回表示の完了を待ち、ビューア上部の **計測結果** を押します。
4. 次ページへの移動、**再読み込み**、必要ならフィルター変更をそれぞれ実行します。
5. **全結果をTSVコピー** し、ChatGPTに貼り付けて区間の比較と原因の切り分けを依頼してください。
6. 繰り返す際は同じデータで3回程度計測してばらつきを確認し、行数・列数を変えたテストでは設定も記録してください。

## 計測区間と意味

| ラベル | 意味 |
|---|---|
| API: extensions.initializeAsync | Tableau Extension APIの初期化待機 |
| API: getVisualSpecificationAsync | 表示列設定に使うTableau APIの応答待機 |
| 設定: フィールド対応全体 | 上記API待機も含む（重複計上禁止） |
| API: getSummaryDataReaderAsync(200) | Reader生成の応答待機 |
| API: getPageAsync(N) | 指定ページの取得待機 |
| API: reader.releaseAsync | Reader解放待機（再読み込み時） |
| 描画: 表の初期化・列対応 | 既存テーブルDOMのクリアと表示列対応 |
| 描画: ヘッダー生成（列幅算出を含む） | 上下2段ヘッダー構築、列幅計測 |
| 描画: 列幅算出（ヘッダー生成の内数） | 列幅の算出時間。ヘッダー時間と重複する |
| 描画: データ型判定・スケール計算 | 表示形式・棒グラフ等の準備 |
| 描画: セルDOM生成 | 行とセルのJavaScript DOMノード生成 |
| 描画: DOMへの追加 | 行DOMをページ内に追加 |
| 描画: 固定列位置計算 | 固定ヘッダー・固定セルのオフセット計算 |
| 描画: renderTable合計 | 上記描画処理全体。内訳と重複する |
| 参考: 次々フレームまで | 描画反映の参考時間。実際の描画完了時刻やGPU負荷の厳密な測定ではない |

表示する「最長の単独区間」は、API呼出しの待機時間とrenderTable全体などの重ならない区間だけを対象とした参考情報で、原因を自動判定するものではありません。

## 解釈と制約
- **初回**: initialize → visual spec → Reader生成 → 1ページ取得 → renderの各区間を比較します。
- **ページ移動**: Readerを再生成せず、getPageAsyncとrenderを比較します。
- **再読み込み**: Readerを解放し、visual specを読み直し、Readerを再生成して1ページ目を取得します。
- **自動更新**: FilterChanged / SummaryDataChanged による再実行を記録します。イベントが連発している場合は回数を確認できます。
- 各APIの測定値は**JavaScriptの呼び出し開始からPromise完了までの経過時間**であり、Tableau内部処理、通信、データ転送を分離した時間ではありません。
- Tableau自身が拡張機能のロード**前**に行うExcel取り込み、抽出生成、ワークシートロード等は計測対象外です。SDKスクリプトのダウンロード時間も対象外です。
- 描画時間はJS実行時間であり、実際のレイアウト・ブラウザ描画・GPU描画すべてを網羅しません。
- 計測パネルが表示中の計測はパネル自体のレンダリング等の影響を受けます。できれば測定後に開いてください。
- 1回の実行ごとに「処理全体」とその内訳を保存します。内数・重複区間があるため、全行の時間を足してはいけません。
- 出力は設定された行数・列数と処理時間等のメタデータだけです。Excelのセル値はコピーしません。
